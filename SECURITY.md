# Reporting a security issue

Report suspected vulnerabilities privately to the organization’s security/product owners. Do not publish customer records, passwords, provider tokens, invitation links or reproduction data containing personal information in a public issue.

Include the release/file-manifest reference, affected role and workflow, safe reproduction steps, expected/observed behavior and likely impact. Use isolated test accounts. Follow the organization’s incident and credential-revocation procedures if a live secret or customer record may have been exposed.

Security properties, check evidence and outstanding release requirements are documented in `SECURITY-REVIEW.md` and `LAUNCH-CHECKLIST.md`. The organization should assign a named security contact and disclosure/incident response policy before launch.
